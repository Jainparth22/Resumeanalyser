# API & Integration Guide

The Space exposes one endpoint, **`/analyze`**, generated by Gradio. It is the same function the web UI uses.

Examples use the public Space `parthjain/ResumeAnalyser` (direct URL `https://parthjain-resumeanalyser.hf.space`). If you duplicate the Space, substitute your own id and URL.

## Request

| Position | Name | Type | Limit |
|---|---|---|---|
| 0 | `resume_text` | string | non-empty, ≤ 20,000 chars |
| 1 | `job_description` | string | non-empty, ≤ 20,000 chars |

Plain text only. Extract text from PDF/DOCX on your side first (e.g. `pypdf`).

## Response

Returns two values: `[report_text, result]`. Integrations should use `result` (JSON). `report_text` is the human-readable version.

```jsonc
{
  "version": "0.3.0",
  "scores": {
    "overall": 63.4,             // 0-100 (see "scorer")
    "scorer": "learned",         // "learned" (fitted weights) or "legacy" (hand weights)
    "semantic": 71.2,            // calibrated whole-document embedding similarity
    "semantic_raw_cosine": 0.7285,
    "coverage": 58.3,            // % of JD skills/keywords found in the resume
    "requirement_coverage": 61.0, // mean cross-encoder evidence score over JD requirements
    "quality": 52.0              // resume writing signals
  },
  "requirements": [              // one entry per JD requirement, with the resume line backing it
    {
      "requirement": "Experience with PyTorch",
      "evidence": "Built models using PyTorch and scikit-learn",
      "score": 0.81,             // 0-1 cross-encoder score
      "status": "met"            // "met" (>=0.5) | "partial" (>=0.2) | "missing"
    }
  ],
  "confirmed_skills": {          // vetted taxonomy: high precision
    "matched": ["Python", "SQL"],
    "missing": ["PyTorch"],
    "matched_via_implication": ["Machine Learning"]
  },
  "other_keywords": {            // KeyBERT: unverified, noisy
    "matched": ["data processing"],
    "missing": ["deploying models"]
  },
  "quality_signals": {
    "action_verb_lines": 3,
    "quantified_lines": 1,
    "missing_sections": ["projects"]
  },
  "suggestions": ["..."]
}
```

Fields may be **added** in minor versions; existing fields are not renamed without bumping `version`.

## Python

```python
from gradio_client import Client

client = Client("parthjain/ResumeAnalyser")
_, result = client.predict(resume, jd, api_name="/analyze")
```

If you have a private/duplicated Space, pass `token="hf_..."` to `Client`.

## curl (two-step, any language)

```bash
BASE=https://parthjain-resumeanalyser.hf.space/gradio_api
EVENT=$(curl -s -X POST $BASE/call/analyze -H "Content-Type: application/json" \
  -d '{"data": ["resume text...", "job description..."]}' | python -c "import sys,json;print(json.load(sys.stdin)['event_id'])")
curl -N $BASE/call/analyze/$EVENT      # server-sent events; the "complete" event holds the data
```

## JavaScript

```js
import { Client } from "@gradio/client";
const app = await Client.connect("parthjain/ResumeAnalyser");
const { data } = await app.predict("/analyze", [resumeText, jobDescription]);
const result = data[1];
```

## Errors & limits

| Situation | Behaviour |
|---|---|
| Empty input | Error: *Please provide both Resume and Job Description.* |
| Input > 20,000 chars | Error: *Input too long* |
| > 10 requests / 60 s per client | Error: *Rate limit exceeded ... Try again in Ns.* Back off and retry |
| Queue full (> 20 waiting) | Gradio queue error; retry with exponential backoff |
| Space asleep | First call after idle takes 30-60 s while the container wakes up |

Recommended client behaviour: timeout ≥ 60 s, retry on rate-limit/queue errors with exponential backoff + jitter, cache results by `hash(resume + jd)`.

## Integration patterns

1. **Job board / ATS plug-in:** call `/analyze` when a candidate applies; show `confirmed_skills.missing` as "skills to add". Use it as a *coaching hint*, not an auto-reject gate.
2. **Resume builder:** call on every save (debounced), render `suggestions` inline.
3. **Batch scoring:** loop with a small worker pool (≤ 2 concurrent, the Space's default concurrency) and respect the rate limit, or **self-host** (below) for bulk work.
4. **Self-host / embed the library:** `pip install -r requirements.txt`, run `python app.py`, or import `resume_analyser.taxonomy` / `resume_analyser.quality` directly (no ML dependencies).
5. **Duplicate the Space** (⋮ menu → *Duplicate this Space*) to get your own instance with your own limits; set `RATE_LIMIT_REQUESTS` etc. under *Settings → Variables*.

## Operator notes

- The limiter identifies clients by the first `X-Forwarded-For` entry (set by the HF proxy), falling back to the socket IP. It is **per process, in memory**; it resets on restart and is not shared across replicas. When self-hosting behind your own proxy, make sure the proxy overwrites that header, otherwise clients can spoof it.
- Do not send data you are not allowed to share: a public Space is a third-party service and inputs are processed on Hugging Face infrastructure.
